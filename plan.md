🛠 Project Handover: Fgrok Extension
1. Project Objective
Create a Chrome Extension (Manifest V3) that surgically removes the "Grok" entry from the primary navigation sidebar on x.com and twitter.com. The solution must be resilient to X’s dynamic loading (SPA) and obfuscated CSS classes.
2. Target Identification
Based on DOM inspection, the target element is:
• Tag: <a>
• Primary Hook: href="/i/grok"
• Secondary Hook: aria-label="Grok"
• Context: Nested within a <nav aria-label="Primary" role="navigation">.
• Constraint: Do not rely on classes like r-6koalj or r-1mkv55d as these are generated at build-time and will change.
3. Technical Requirements & Stack
• Standard: Manifest V3.
• Permissions: host_permissions: ["https://x.com/*", "https://twitter.com/*"].
• Injection Strategy: Dual-layer approach (CSS for speed + JS for persistence).
4. Implementation Files
A. manifest.json
The manifest must register both a CSS file and a JavaScript content script.
{
  "manifest_version": 3,
  "name": "X-Grok-Cleaner",
  "version": "1.0",
  "content_scripts": [
    {
      "matches": ["https://x.com/*", "https://twitter.com/*"],
      "css": ["style.css"],
      "js": ["content.js"],
      "run_at": "document_start"
    }
  ]
}

B. style.css (Layer 1: Instant Suppression)
This handles the "flash of unhidden content" (FOUNC) by hiding the element as soon as the browser parses the HTML, often before the JS runs.
/* Select by stable attributes */
a[href="/i/grok"], 
a[aria-label="Grok"] {
    display: none !important;
}

C. content.js (Layer 2: Dynamic Persistence)
Since X is a Single Page Application, the sidebar may be re-rendered or injected after the initial load. A MutationObserver is required.
Logic Requirements:
1. Selection: Target a[href="/i/grok"].
2. Observer Config: Watch document.body for childList and subtree changes.
3. Efficiency: The callback must be lightweight to avoid performance lag during scrolling.
const hideGrok = () => {
    const target = document.querySelector('a[href="/i/grok"]');
    if (target && target.style.display !== 'none') {
        target.style.setProperty('display', 'none', 'important');
    }
};

// Observe the DOM for dynamic navigation changes
const observer = new MutationObserver((mutations) => {
    hideGrok();
});

observer.observe(document.body, {
    childList: true,
    subtree: true
});

// Initial execution
hideGrok();

5. Execution Steps for the Agent
1. Initialize Project: Create a folder with the provided manifest.json, style.css, and content.js.
2. Refinement: If the "Grok" text appears in other areas (like the "More" menu), expand the selectors to include [aria-label*="Grok"].
3. Packaging: Ensure all files are in the root directory.
4. Testing Protocol: * Load the unpacked extension in chrome://extensions. • Navigate to https://x.com/home. • Verify the sidebar item is gone. • Refresh the page multiple times to check for "flickering." • Navigate between "Home" and "Notifications" to ensure the MutationObserver catches the re-rendered sidebar.
6. Success Criteria
• The Grok button is 100% invisible upon page load.
• The layout of the remaining sidebar items remains intact (no awkward gaps).
• Zero console errors generated by the extension.
